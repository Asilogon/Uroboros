# Конвенция коммитов проекта Uroboros

## Формат сообщения коммита

```
[0.0.0] Краткое описание

Подробные изменения:
- Пункт 1
- Пункт 2
- Пункт 3
```

## Правила

### 1. Строка заголовка (subject)
- Формат: `[X.Y.Z] Краткое описание`
- `X.Y.Z` — версия проекта в семантическом формате (SemVer):
  - **MAJOR (X)** — несовместимые изменения API
  - **MINOR (Y)** — новая функциональность (обратно совместимая)
  - **PATCH (Z)** — исправления багов (обратно совместимые)
- Краткое описание — до 72 символов, в повелительном наклонении ("Добавлено", "Исправлено", "Обновлено"), с заглавной буквы, без точки в конце.
- Начинается с версии в квадратных скобках, затем пробел.

**Примеры:**
```
[0.1.0] Добавлен GUI-интерфейс в стиле IDE
[1.0.0] Первый стабильный релиз API-клиента
[0.0.5] Исправлена утечка cookies при повторной авторизации
```

### 2. Тело коммита (body)
- Отделяется от заголовка пустой строкой.
- Начинается с `Подробные изменения:` (или `Changes:` для англоязычных коммитов).
- Каждый пункт — с новой строки, с маркером `-`.
- Описывает ЧТО и ПОЧЕМУ изменено, а не как.
- Максимальная длина строки — 72 символа (мягкое ограничение).

**Пример полного коммита:**
```
[0.2.0] Добавлена поддержка DeepSeek-R1 Thinking

Подробные изменения:
- Реализован стриминг reasoning_content в send_message()
- Добавлен переключатель моделей в GUI (V3 / R1 Thinking)
- Обновлён CLI: новый пункт меню [8] для выбора модели
- Исправлен баг с дублированием токенов в session.json
- Обновлена документация README.md с примерами reasoning
```

### 3. Версионирование
- Версия в заголовке коммита отражает состояние проекта ПОСЛЕ применения изменений.
- Один коммит = одна версия.
- Для нескольких мелких правок подряд допускается инкремент PATCH.
- При значимой новой функциональности — инкремент MINOR.
- При breaking changes — инкремент MAJOR.

### 4. Запрещено
- ❌ Коммиты без версии в квадратных скобках
- ❌ Версия не по SemVer (например, `[1]`, `[0.0.0.1]`)
- ❌ Пустое тело коммита для изменений больше 1 файла
- ❌ Тело без префикса `Подробные изменения:`
- ❌ Смайлики и нецензурная лексика

### 5. Рекомендуется
- ✅ Атомарные коммиты (одна логическая правка = один коммит)
- ✅ Запускать тесты перед коммитом
- ✅ Проверять `git diff --staged` перед коммитом

---

## Автоматизация

Используйте скрипт `scripts/commit.ps1` для интерактивного создания коммитов по конвенции:

```powershell
.\scripts\commit.ps1
```

Скрипт спросит версию, краткое описание и пункты подробных изменений, а затем выполнит `git add -A` + `git commit` с правильно отформатированным сообщением.
